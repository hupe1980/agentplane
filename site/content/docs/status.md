`agentplane` is pre-alpha. The first table is the honest inventory: every row is
a capability that exists in the code, with the tests that hold it. The design
decisions below record both recent hard cuts that are now built and the few
deliberately deferred items, so an old design note cannot masquerade as current
implementation status.

The rule this page follows: **a row appears only when something would fail if the
capability were removed.** A feature with no test that can falsify it is not a
feature, it is an intention — the mechanisms that make that checkable are in
[operations](@/docs/operations.md).

## ✅ Built

| | |
|---|---|
| ✅ | **Tenant-keyed storage** — the tenant is a **key component** of every row on both backends, never a filter: a query that forgets it returns nothing rather than another tenant's rows. redb keys the journal, seal log, cases, events, timers, tasks and batches; `PostgreSQL` leads every primary key, unique index and foreign key with it. The tenant leads every time-ordered index, so a sweep or a worklist *ranges over* its own rather than filtering another's out, and counts are ranged rather than taken from the table. Two correlation paths matter most, both reachable because business keys are not globally unique: the case correlation index (a run joining another tenant's case would share its history, deadlines and erasure unit) and the subscription match index (one tenant's message resuming another's waiting run). Checked against a real Postgres with a *valid* identifier from the other tenant, which is the realistic leak → [erasure and keys](@/docs/erasure.md) |
| ✅ | **Tenant-aware serving** — one process serves many tenants: `Planes` maps an authenticated caller's tenant to that tenant's plane, and the gate hands the route the plane *with* the caller, so a handler cannot reach a store it did not resolve — the cross-tenant read is unspellable rather than guarded against. A caller whose tenant has no plane is **refused, never defaulted**, since a fallback turns an unregistered tenant into somebody else's data. Each plane answers under its **own** policy engine, so the laxest tenant's rules cannot set everybody's. The tenant comes from the credential like `actor` and `roles`, and on A2A it is checked twice — against the card *and* against the credential, because those can disagree and the disagreement is the attack. **Blob paths lead with the tenant**: content addressing otherwise puts two tenants' identical bytes in one object, and erasing it for one destroys the other's data while reporting both requests discharged → [erasure and keys](@/docs/erasure.md) |
| ✅ | **Break-glass, and it writes to the tenant it crossed** — every other tenancy control makes a cross-tenant read *unspellable*; this is the designed exception, and an exception with no record is indistinguishable from the breach it is meant to be. `record_break_glass` seals the crossing — actor, roles, and a **mandatory** reason, refused blank — into the journal of the tenant whose data is about to be reached, so it inherits that tenant's hash chain, per-record signature and Merkle inclusion, is findable by `GET /runs?outcome=broke-glass`, and the offline audit reports it without being taught what break-glass is. **The record is written before any data is served, and failing to write it fails the access**: the alternative — serve, then record best-effort — is a break-glass that works exactly as well when its own evidence is lost. Who may pull it is a policy question the deployment's own engine answers, not one this crate decides → [operations](@/docs/operations.md) |
| ✅ | **Per-tenant quotas** — ceilings on runs executing at once and on spend per billing period, accounted **in the store**, so they survive a second instance rather than doubling the moment somebody scales out. The reservation is one transaction that counts *and* inserts: a read-then-write leaves a window two instances admit through, and it widens under exactly the load the ceiling exists for. A refusal is its own error, not a policy denial — one says *you may not*, the other *not right now*, and collapsing them teaches callers to retry denials or abandon work that would succeed in a second. Checked at admission, so a refused run writes nothing; **never** on replay, or a ceiling crossed since would rewrite history into a refusal. Concurrency is a *set* of runs, not a counter: a crashed process strands a slot an operator can name rather than a number that has silently drifted. One battery holds both backends to it → [operations](@/docs/operations.md) |
| ✅ | **Per-tenant metric labels** — opt-in and **off by default**, because a tenant name is often a customer name and a metrics backend is usually the least protected system in a deployment. Cardinality is bounded by *configuration*: the label is this plane's own tenant, so the number of streams is the number of planes an operator wired and no request can grow it. There is deliberately no pseudonymous option: the tenant already appears in store keys, blob paths, the checkpoint origin and a publicly served Agent Card, so hashing it here would cover one exit of ten and invite the belief that it is contained — an id that is opaque to begin with covers all of them → [operations](@/docs/operations.md) |
| ✅ | Append-only, hash-chained journal — no record can be edited, reordered, or removed *within* a run |
| ✅ | **Record attestation** — every record optionally signed under a named identity, so the journal says *who wrote it*, not only what it says |
| ✅ | **Cross-run binding** — sealed runs enter a per-plane Merkle log with inclusion *and* consistency proofs, so an auditor can tell ordinary growth from a deletion; the per-run chain structurally cannot see either |
| ✅ | **Offline audit** — `audit::audit` runs against a store it did not write, and reports what it *could not* check as loudly as what failed |
| ✅ | **A sealed journal refuses appends — as a store constraint** — the Merkle leaf is the chain head *at seal time*, and the caller that sealed a run is exactly who still holds the current epoch, so without this check that caller could advance the true head past the leaf every checkpoint attests. The executor's own refusal to resume a closed run is application logic a future caller can bypass; the refusal now lives inside the append transaction on **both backends**, beside the fence, as `StoreError::RunSealed`. Held by a conformance case that seals a run, appends under the still-valid epoch, and asserts both the refusal and an unmoved head |
| ✅ | **A conclusion is not a closure** — `failed` and `exhausted` are conclusions a resume can honestly answer: completed effects are read back from history rather than performed again, which is the point of having a journal. So they no longer **seal** — a failed run stays open, findable under `GET /runs?outcome=failed`, and resumable — because sealing it entered it into the Merkle log at its mid-failure head, and its own legitimate resume then grew the history past the leaf every checkpoint attested, while the outcome index (first-seal-wins) listed it as failed forever even after it succeeded. Three silent disagreements from one conflation. Only `succeeded`, `quarantined` and `cancelled` freeze the journal; `RunStatus::seals` is the one implementation of that rule, resume refusal agrees with it, and an outcome this build does not recognise refuses to resume — **fail closed**, where it used to fail open. Worth naming against the field: Temporal's failed workflow is terminal and its retry starts a fresh run that re-executes completed activities; here the resume is the same run and the invoice already issued is read back, not re-issued |
| ✅ | Effect protocol — announce durably, act, record; at most once per run |
| ✅ | Replay (`Strict` verification) and resume (`Resume` crash recovery) |
| ✅ | Divergence detection — a changed build is quarantined, never allowed to silently rewrite history |
| ✅ | Exactly-once as a *database constraint*, not a code path |
| ✅ | **Run-ownership leases with epoch fencing** (split-brain safety), **renewed while a run executes** — the TTL bounds how long a *crashed* owner strands its runs, not how long a run may take. Without renewal a healthy run outliving its TTL is indistinguishable from a dead one, and is taken over and fenced mid-flight. A TTL under two seconds is refused at build: the stores keep expiry in whole seconds, so a shorter lease lapses between renewals however often they run |
| ✅ | Information-flow labels — trust/sensitivity lattice, egress ceilings, taint gates; **effect output is labelled at the source, untrusted by default** |
| ✅ | **Hierarchical argument provenance** — structured JSON retains labels per RFC 6901 path through plan field projection and object/array assembly. Outbound effects must use `cx.sink`, which canonically binds the exact dispatched arguments to the labels checked; generic `cx.effect` refuses them |
| ✅ | **Protected sink fields** — mutating tools can require trusted data, named provenance sources, and field-specific sensitivity ceilings for authority-bearing selectors while allowing ordinary untrusted content beside them. Manifest declarations are digest-covered and must exactly match the live catalogue |
| ✅ | **Typed, policy-authorized release** — trust and/or sensitivity can improve for the whole value or exact tracked fields only; every decision names its destination, basis and evidence, is authorized under `data:release`, retains provenance, and is journaled with the value digest plus prior/result labels. Release decisions occupy ordered effect keys, so changed evidence or semantics is replay divergence and strict replay never re-opens policy |
| ✅ | Journaled clock; reproducible per-step RNG |
| ✅ | Record schema versioning with pure upcasters |
| ✅ | **Cases** — correlation by business key, state across runs, closure rules |
| ✅ | **The instruction slot is authority-bearing** — `/system` is a protected field on a model call, so an instruction must be *trusted*. A model reads its order and its data as the same undifferentiated text, so a retrieved document saying *ignore previous instructions* is obeyed like one; every other control here bounds what the model may then **do**, and none of them answers who was allowed to give the order. Untrusted material belongs in `messages`, which forces the prompt to be built with `Tainted::object` — `map` cannot prove how a closure reshaped a value and taints the instruction with it → [security](@/docs/security.md) |
| ✅ | **Governed memory** — versioned items an agent or team keeps between runs, on redb **or PostgreSQL** under one conformance contract. Runtime writes accept `MemoryWrite` plus `Tainted<Value>` and derive trust/provenance/sensitivity, so storing model output cannot act as an unjournaled release. Retrieval commits to ids, versions, content and security metadata. Concurrent revisions serialize; cascading erasure is one backend-atomic graph operation and serializes against derivative creation; ids cannot move scopes or be recycled → [architecture](@/docs/architecture.md) |
| ✅ | **Compaction** — `cx.compact` summarises memories into a *derived memory*, and every hazard in that sentence is answered by the effect's shape. Its label is the **join of its inputs** and never declared by the caller, so summarising cannot launder untrusted memories into trusted ones. It carries a `max_sensitivity` ceiling on what the summarising model may be shown, defaulting to `Public`, because compaction is an *egress*. It records and validates exact source versions/commitments and remains in their subject, so subject erasure cannot strand a summary elsewhere. `forget` is correction and retains lineage; `forget_cascading` is erasure and traverses it → [security](@/docs/security.md) |
| ✅ | **Deadlines** — pluggable `Calendar`, journaled instants, due sweep |
| ✅ | **Durable waits** — suspend on a correlated event; a waiting run is a row, not a thread |
| ✅ | **Durable timers** — `cx.sleep()` suspends the run; a sweep wakes it, and the instant is journaled |
| ✅ | **Event delivery** — arrival-order-independent, dead-lettered by sweep, deduplicated on **`(source, id)`** as CloudEvents defines uniqueness. Over HTTP the source is the authenticated caller, never a body field. The sender is journaled with the await and appears in provenance as `sender:…`, so a protected field can name one counterparty → [security](@/docs/security.md) |
| ✅ | **Human tasks** — worklist, four-eyes enforcement, declared expiry policy |
| ✅ | **Sweeper** — deadline warnings, breach escalation, task expiry, dead letters |
| ✅ | **Plan DAG** — contract validation, **concurrent** ready-set scheduling, provenance binding |
| ✅ | **Topology** — collaboration must justify itself; false parallelism is rejected |
| ✅ | **Replanning** — versioned successors with lineage; refused once untrusted data is in play |
| ✅ | **Budgets** — step/effect/token/cost/wall-clock limits, enforced deterministically |
| ✅ | **Retries** — gated on whether the call reached the peer, not on how the error looked |
| ✅ | **Reconciliation** — resolve an unknown outcome by asking the provider, not by assuming |
| ✅ | **Sagas** — reverse-order compensation, pivots, suspendable unwinds, and a refusal to unwind around doubt |
| ✅ | **Every case mutation is an effect** — a case's status and its obligations are shared mutable state that outlives the run, so both changes are journaled and neither is performed again on replay. A write outside the journal has two holes and the second is worse: replaying last quarter's history to answer a question would close a case that has since been reopened, and *who closed this and when* would have no record at all |
| ✅ | **Every feature builds alone** — `--all-features` cannot catch a feature that uses a module it never declared, and neither can a curated combination: it compiles whenever something else in the set happens to enable that module. `a2a-server` did exactly that with `push` and had never once been compiled by itself. `just features` now builds each optional feature on its own |
| ✅ | **The authorization decision can be re-derived** — policy is total and side-effect free so a third party can reach the same verdict offline, which only works if every input it consulted is on the record. The outbound value's **label** reached the policy request one revision before it reached the journal, so for that revision an auditor had to take the runtime's word that the right label was presented. `EffectStarted` now carries it, absent when an effect binds no value → [security](@/docs/security.md) |
| ✅ | **A specialist cannot hand off, in-plane either** — the role forbids delegation and the manifest refuses a specialist declaring a depth above zero. That was the *declaration* half, and for a while it was the only half: the ceiling was checked at delegating **sinks**, so it governed the A2A peer call and not `cx.commission` — the rule held across a network boundary and not across a function call. The loop the role exists to prevent, A→B→C→A, is the in-plane one: one process, no peer boundary to cross, no allowlist to notice. The check now sits on the path both take |
| ✅ | **A quarantine you can find** — a quarantine is the most serious conclusion this runtime reaches, and it used to produce a run status, an `error!` event and a counter: nothing an operator could ask for, and a run started with `spawn` returns before the status exists. Concluded runs are indexed by how they ended, `GET /runs?outcome=quarantined` lists them, and the index is **derived** — the store maintains it from the `RunSealed` record inside `append`, so the outcome's home stays the chain, it can be rebuilt, and it is never an authority. **The last conclusion wins**: a failed run that is resumed and succeeds moves between listings rather than being listed as failed forever, which is what keeps the failed backlog drainable. Longitudinal studies of production agent runtimes name this shape as the dominant failure: not an undetected fault, but a detected one whose signal never reached a human → [operations](@/docs/operations.md) |
| ✅ | **One matter, one scan** — the journal carries a record's case and indexes it, so *show me everything about this matter* is a range scan rather than a join over the case's runs. The difference is not only cost: a per-run walk **misses** every record written by a run the case does not own, which is exactly what a sweep is — so the record saying why a case was escalated would be unreachable from that case. Tenant-first, held to one conformance battery across both backends, and the battery checks that the scan finds this matter *and* returns no other |
| ✅ | **The sweep writes its own history** — breaching an obligation and escalating a case are the most consequential things the plane does *without being asked*, and nothing else records them. A tick that decides anything writes `Swept { subject, action, detail }` into a **sealed run of its own**, so it inherits the chain, the signature and the Merkle inclusion, and the external audit tool checks it without being taught what a sweep is. State alone cannot tell *the sweep breached this at 02:00* from *somebody set it*. A quiet tick writes nothing → [operations](@/docs/operations.md) |
| ✅ | **A capped sweep says it was capped** — each tick takes a bounded batch, because a sweeper still draining a backlog is one not noticing the next obligation. A bounded query returns a list shaped exactly like a complete one, so `SweepReport::saturated` names which sweeps came back full and `needs_attention()` is true when any did — otherwise a growing backlog and a quiet plane produce identical numbers → [operations](@/docs/operations.md) |
| ✅ | **A sweep whose evidence is lost says so, not nothing** — a tick that breached obligations and then failed to write its own sealed record used to return the *same* empty `record` as a quiet tick, so a decision with no durable account of who made it read as inactivity — the I13 failure the sweep's own run exists to prevent. `seal` now distinguishes quiet from evidence-lost, `SweepReport::evidence_lost` carries it, and `needs_attention()` is true when it is set. Held by a test that fails the sweep's `Swept` append and asserts the breach still happened while the report demands attention → [operations](@/docs/operations.md) |
| ✅ | **Closing a case is closing it everywhere** — a case's status and its correlation-open membership are two spellings of "closed", and the only agent-reachable path (`set_case_status(Closed)`, the `SetCaseStatus` effect) wrote the status column and left the keys, so a closed case stayed correlatable and a new matter attached to it — and it skipped the open-obligation check that stops a missed regulatory window hiding behind a tidy status. Closing now runs the full ceremony on both backends: release the keys, refuse an unmet deadline. The shared conformance battery closes a case through the agent path and asserts it is no longer correlatable, because `close`, which had the ceremony, has no agent surface — a battery exercising only it proved a path nobody takes → [erasure and keys](@/docs/erasure.md) |
| ✅ | **A deferred member that *landed* quarantines, never cheap-aborts** — the abort path's completeness check excluded only `InDoubt`, so a deferred member returning `Landed` (a provider answering 200 with an unusable body) was read as "nothing externalised" and took the cheap abort — the journal settling `Aborted`, *taken back whole*, over a send that went out. The predicate is now `may_have_externalised`: the cheap abort is available only when the member provably did **not** reach the world. Held by a guard test whose deferred member fails `Landed` and a TLA+ mutant that aborts over an externalised member → [architecture](@/docs/architecture.md) |
| ✅ | **The Vault token never reaches a log** — `VaultTransit` held its auth token in a bare `String` under a derived `Debug`, reachable through the derived `Debug` of `Runtime`, `StepCtx` and `RuntimeBuilder`: one `tracing::debug!` from printing it verbatim, the one credential holder in the crate not hand-redacted. It is now a `Secret` — redacting and zeroizing — like every other credential here → [security](@/docs/security.md) |
| ✅ | **An A2A decline carries no reason** — the admission gate returned Cedar's denial verbatim, naming the determining policy ids and the action/resource to an external caller: a probe-able map of the authorization vocabulary. The caller now learns only that it was declined; the determining policy stays operator-side in a `tracing` event, tested by asserting the policy's secret rule name does not appear in the response → [security](@/docs/security.md) |
| ✅ | **Transactional effect groups** — the unit between an effect and a step, because a per-step saga leaves a gap: `Skill::compensate` receives the step's *output*, and a step that failed has none, so it is handed the absence of one and asked to guess. A group declares the **resources it touches** and refuses any member outside them; each reversible member records the concrete call that undoes it, built from that member's **actual output at the moment it landed** rather than reconstructed later from state that has moved. `commit` is the **frontier** — invariants are checked there because it is the last instant at which failing them is free — and only then are **deferred** members released. Deferral is what makes an irreversible send safe: an aborted group never sends it, which is a stronger statement than sending and apologising. Reversals dispatch through the ordinary effect path, so an undo is journaled, keyed, retried and metered like any other call, and never runs twice. Doubt reverses nothing. And once the atomic members' transaction commits, the cheap abort is gone: a deferred failure then **quarantines**, because `Aborted` claims *taken back whole* over a permanent write with no reversal registered and none possible — a hole the code, the model's invariant and the model's constants were all silent about at once. **The footprint now bounds the ambient surface too**: a mutating effect dispatched while a group is open is refused unless it is a member's own dispatch, because it would otherwise register no reversal, survive the unwind, and leave `Aborted` claiming the world was taken back whole over a write still standing — the same falsehood reached by a third route. Reads stay legal and a positive test holds that half, so a refuse-everything change cannot pass → [architecture](@/docs/architecture.md) |
| ✅ | **Tracing** — run/step/effect spans, a dedicated event per loud failure, replay marked distinctly |
| ✅ | **Batches** — one frozen plan over N items, per-item journals, item-granular resume, partial failure as a terminal state |
| ✅ | **Delegation** — attenuating chains from a human owner down to the acting workload; widening is unrepresentable |
| ✅ | **Tool calls** — an operator-declared catalogue; a server's `readOnlyHint` can never make its own tool safe to repeat |
| ✅ | **Model calls** — usage journaled, and a completion that dies partway is billed for what it generated |
| ✅ | **Peer calls** — audience-bound credentials obtained by token exchange, refreshed before expiry, and never written to the journal |
| ✅ | **MCP host surface** — real round trips over `rmcp`, behind the `mcp` feature: exact operator/manifest-granted prompts and resources are untrusted journaled effects; tools preserve structured or text/image/audio/resource blocks; asynchronous tool results become typed `McpTask` handles with journaled `tasks/get`, governed `tasks/update`, and idempotent cooperative `tasks/cancel`. `McpClient::host_info` negotiates Tasks and deliberately omits elicitation, sampling, roots and subscriptions because none has a governed runtime callback path. Every transport failure states whether the operation reached the server |
| ✅ | **A tool reference names the tool, never the transport** — grants are `tool://server/name`, and which transport reaches a server is wired at deployment. The old `mcp://` spelling was a supply-chain claim in a review artifact, asserted for tools compiled into the binary and republished to peers on an Agent Card. It also made one manifest untestable against an in-process double. The server component is now load-bearing: `ToolRouter` gives each server its own client, so two servers offering `read` stay two tools, and a plane may use typed in-process tools **and** MCP at once — which a single client handed every id could not express |
| ✅ | **An MCP client refuses another server's tool** — it dispatched anything it was handed against whatever connection it held, so a plane granting one server's tool and wiring another's got a **successful answer from the wrong server**, under the first one's operator safety. Nothing downstream could see it. Now `Unreachable`, naming both servers, because nothing was attempted and nothing could have been |
| ✅ | **Embedding is a journaled effect** — `StepCtx::embed` records the query vector beside the model revision that produced it. The vector is inside the semantic-retrieval effect's identity and an embedding service does not promise the same floats twice, so a skill computing its own would quarantine a healthy run on the next replay with nothing on the record to explain it. Held by a test whose embedder deliberately drifts, because a stable stub would pass under a runtime that recomputed |
| ✅ | **Every published YAML *fragment* parses too** — the manifest guard keys on `apiVersion`, which is exactly right for a whole agent and reads none of the excerpts. Excerpts are most of what the cookbook publishes and are the thing a reader copies *into* a manifest they already have, so a broken one fails in their editor and in nobody else's. Two were broken, both by indentation a reviewer's eye slides over: `protected_fields:` sitting deeper than the sibling keys of its own list item, and prompt/resource grants whose keys sat deeper than the `- server:` that introduced them. Parsed as plain YAML rather than as a `Manifest`, since the question an excerpt raises is whether the shape is syntactically real, not whether it is a complete agent |
| ✅ | **Every documented API name exists** — the reference tables are prose to every tool in the toolchain: doc tests compile rustdoc under `src/`, never the markdown, and the snippet harness builds only the first example a reader meets. So the concepts page's `StepCtx` table — the surface a newcomer programs against — published `random()`, `write_case_state()` and `read_blob`, none of which are methods on the type, and nothing noticed. Two guards now read the code and refuse a name that is gone: every method a page names — in a snippet, in a rustdoc reference, or bare in that table — is checked against the `impl StepCtx` blocks **across the whole runtime module**, and every field the manifest reference tabulates is checked against the parser's own structs, where a stale name costs a reader a `deny_unknown_fields` failure rather than a warning. Both are one-directional — a page choosing what to teach is editorial — and both assert they read a plausible number, because a walk that found nothing satisfies every prohibition by having nothing to prohibit. The first version of the method guard **passed with the defect reinstated**: the table publishes the name bare, in backticks, which the snippet and rustdoc markers do not see — so it walked straight past the exact thing it was written for |
| ✅ | **No doc comment has absorbed the one below it** — inserting a method between an existing doc block and its function is valid Rust, valid rustdoc, and silent: one published page then describes the wrong operation while another describes nothing. It happened twice. `StepCtx::draw` — which spends a customer's standing authorization — was published under "Recall what this agent remembers about a subject", and `StepCtx::store_blob`'s documentation was published on `blobs()`. The fingerprint is a block carrying two `# Errors` sections, because that is a section one item has at most one of. Deliberately narrower than `missing_docs`, which fires 1124 times here — almost all on builder methods whose names already say everything, so it would have buried this rather than found it |
| ✅ | **Every published manifest parses** — a YAML snippet in a document is a thing a reader copies and nothing in the toolchain reads it: doc tests compile Rust under `src/`, never markdown. The architecture page's flagship agent declared `role: specialist` beside `max_delegation_depth: 2`, which this crate's own parser refuses, so the first command a reader ran failed. A guard now parses every manifest on the site and in the README with `Manifest::parse` itself rather than a second copy of the rules |
| ✅ | **A tool body reports a disposition, not a transport error** — `Tool::call` returns `ToolFailure::{DidNotHappen, InDoubt, Landed}`. It used to return the wire vocabulary, which asked an author writing their own logic to translate into facts about a connection they do not have — and to name their own `ToolId` on every error path, with nothing stopping them naming a different tool. The id is attached by the box that dispatched the call, and the mapping to `Disposition` is pinned by a test, because getting it wrong in the `DidNotHappen` direction is how a payment happens twice |
| ✅ | **Every published Cedar policy is executed** — the site's only worked taint gate read `context.args_trust`, an attribute the runtime has never sent. Cedar is *total*, so the `when` clause did not raise: the `forbid` was unsatisfied, the accompanying `permit` stood, and the gate an adopter would have copied **failed open** while every test around it passed — each one having built a context containing the invented key. Documented policies now run against a matrix of real request contexts and must produce more than one decision, because a rule that parses and distinguishes nothing is the exact shape being guarded against |
| ✅ | **A media block builder and its driver cannot drift** — each provider's block shape had two implementations: the builder that produces it and the driver that parses it back. Both had tests, both built their own JSON by hand, and nothing fed one to the other — so a renamed key would have stopped multimodal dispatch for that provider while the whole suite passed. The producer's real output now goes through the real consumer, and a mutation renaming a key kills it |
| ✅ | **Every example is executed** — `just examples` is the only thing that runs example code, so one missing from that recipe compiles forever and never runs, while the README points readers at it. `memory_run` was in exactly that state. A guard now checks the recipe against the directory; the `_live` examples are exempt by name, because a credential being available is not a decision to spend it |
| ✅ | **Trust outranks recency in recall** — retrieval truncates to a limit, and ordering that window by recency alone is an eviction an attacker steers: anything able to write an untrusted memory — model output and tool output both can, by design — writes `limit` of them and every trusted memory silently loses its place. The caller receives exactly the number it asked for, each item honestly labelled, with no signal that a trusted one existed and did not fit. The defect was in the **ordering, not the labelling**, which is what made it invisible. Trust now leads the retrieval index on both backends rather than being sorted afterwards, and the shared conformance battery holds them both to it. Untrusted memories still fill the remaining room — an agent that cannot see what it was told is a different defect |
| ✅ | **An emergency stop that survives a restart and a second instance** — `set_halt(Some(reason))` refuses new admissions for one tenant, from a flag in the **store**: an in-process switch stops only the instance it was thrown on, which is the in-process-counter failure arriving during an incident. Checked *before* the no-ceilings shortcut, because a tenant with no quotas is the one most likely to need stopping, and it fails closed like every other admission check. The refusal is its own error, not a ceiling — a ceiling says *not right now* and invites the retry a halt exists to stop. It stops **new work only**: runs in flight and suspended runs resuming are existing work, and refusing those would strand them mid-saga with reversals unrun. Cancel is how you stop work already started |
| ✅ | **A person approves the call, not a summary of it** — `requires_approval: true` on a tool grant opens a task carrying the **exact tool reference and the exact arguments** about to be dispatched, and the call does not happen until somebody approves. ## 🧭 Design decisions and remaining gaps

✅ rows are implemented hard cuts whose rationale is worth retaining; ⬜ rows
remain unimplemented. Each open row says why it is still deferred, so an
evaluator can tell "deliberately deferred" from "never thought about" — the
distinction a status page exists to make.

| | |
|---|---|
| ✅ | **A tool is one type** — its arguments are its fields and its schema comes from those fields, so a model is shown exactly what the body will receive. Model-steering prose stays in the digest-covered manifest, where changing it becomes a reviewed version change. `call` takes `self`: by the time it runs the model's JSON *is* the type or the call was refused, so there is no `Value` to index and no field to misspell — the old shape read `arguments["id"].as_str().unwrap_or(…)` and turned a renamed field into a plausible wrong answer. Dispatch by name happens once inside the crate rather than in an `if` at the top of every `ToolClient`. And `RuntimeBuilder::toolbox` makes that one call: it derives the catalogue from each agent's own declaration and **refuses to build** where the code and the reviewed manifest have drifted **either way** — a tool implemented but never granted, or granted with nothing behind it, or a manifest relaxing a tool's own claim that it mutates. The check runs at `build` rather than when the box is wired, so it cannot be lost by reordering the builder, and every agent on the plane is checked rather than the first |
| ✅ | **A catalogue may be stricter than a grant, never laxer** — the two places a tool's safety can be written are the reviewed manifest and the operator's catalogue, and only one of them is what the *effect* reads. A catalogue calling a reviewed-mutating tool read-only therefore drops the whole-value taint gate and makes a timed-out money-moving call retryable, which is the one direction nobody can be right about. Refused at build; and the taint gate takes the stricter of the two regardless, because the authorization gate had ORed the manifest's `mutates` in since it existed and the sink gate beside it had not. Two agents on one plane granting one tool **differently** is refused for the same reason: a plane has one catalogue, so merging by last-writer resolves a reviewed disagreement by registration order and refuses the losing agent every call to that tool, in production |
| ✅ | **A tool is declared once** — `ToolCatalog::from_manifest` derives the operator's catalogue from the agent's declaration. A manifest and a catalogue are two parties speaking, which is real when they are two people and pure tax when they are one: stating `mutates`, the ceiling and the protected fields twice is one decision written twice and a chance to disagree about it. An operator who genuinely differs still calls `.allow(...)`, and the manifest's grant is re-checked at dispatch either way — deriving can only narrow, never widen |
| ✅ | **A failed tool call says only what the model may act on** — the far side's own answer reaches it, because a tool that was unreachable or ran and declined is what the model needs in order to try something else, and it is text the far side already controls. A refusal produced *here* is one uniform sentence. And an outcome that is **unknown** is not a failed call at all: it leaves the loop so the executor quarantines, because a timed-out payment may well have been taken and reporting it as a failure lets the model apologise, continue, and end the run `Succeeded` over a mutation nobody can account for → [security](@/docs/security.md) |

## 📌 What to pin, and what will move

Pre-alpha means every one of these can change. It does not mean they are all
equally likely to, and an adopter deciding what to build against deserves the
difference rather than one blanket warning.

Nothing here is a compatibility promise. It is a statement about where the
remaining design pressure is.

| Surface | Expect | Why |
|---|---|---|
| **Effect / disposition / recovery vocabulary** | stable | `DidNotHappen`/`InDoubt`/`Landed` and the recovery classes are the load-bearing idea; changing them would be a different system |
| **`Skill`, `StepCtx` core methods** | stable in shape, additive | new capabilities arrive as new methods; existing ones are not expected to change signature |
| **Journal record format** | **will change** | not frozen. Upcasters exist, but a format-freeze milestone has not happened and hard cuts are preferred until it does |
| **Effect keys** | **will change** | any change to a descriptor's arguments moves every key for that effect kind. `tool.call` was `mcp.tools/call` until the reference scheme stopped naming a transport |
| **Manifest schema** | additive, with hard cuts | `deny_unknown_fields` means an added field is safe and a *removed* one is a hard failure. Fields have been removed when they could not be enforced — see the design decisions above |
| **`Tool` / `ToolFailure`** | recently changed | `Tool::call` returns `ToolFailure` (disposition-named) rather than `ToolError` (transport-named); references are `tool://server/name` |
| **Policy seam (`PolicyEngine`, request context)** | stable seam, growing context | the trait is settled. `context` gains attributes as the runtime learns to say more, and a policy reading one that does not exist **fails open** — see [security](@/docs/security.md#the-authorization-context) |
| **Store traits** | stable seam, growing contract | the conformance battery is the contract; it gains cases faster than the traits gain methods |
| **Store schemas, SQL *and* redb** | **will change without migration** | pre-alpha, and there is no migration tooling. Recreate rather than migrate. This covers both backends deliberately: a redb `TableDefinition` pins its value types, so widening a column is as breaking as an `ALTER TABLE` and fails at open rather than at read. Making money unsigned moved the quota, batch and authority tables on both |
| **A2A / MCP wire behaviour** | tracks the specs | exact released versions, not a compatibility range — see the open protocol-support question in the design decisions above |
| **`testkit`** | stable, additive | it is how embedders test their own stores and skills, so churn here costs more than it saves |

## 🔍 How to check this page is honest

```sh
just anchors    # every mutation still anchors in the code it names
just features   # every optional feature compiles on its own
just audit      # no dependency in the tree has a known advisory
just ci         # lint, feature configurations, examples, docs, packaging
just ci-full    # the above, plus TLA+ specs and the full mutation sweep

python3 tools/mutants.py <name> --verify   # one guarantee, end to end
```

The mutation sweep is the one that matters for this page: it breaks each
guarantee on purpose and requires the test *written for it* to fail. A row here
whose guarantee could be deleted without a test noticing would be caught by that
sweep, not by review.

`--verify` is the same check for a single row, and it exists because the cheap
one is not enough. `just anchors` proves a mutation still *matches* the code;
only running it proves the mutation still *kills*. A test rewritten around a
mutation passes quietly, and a guarantee that stopped being checked looks
exactly like one that is. The feature set comes from the test's own `cfg` gates
rather than a second list, so there is nothing to keep in step — and the command
distinguishes **survived** from **never ran**, because a run that compiled
nothing reports zero failures and reads like success.
