`agentplane` is pre-alpha. This page is the honest inventory: every row is a
capability that exists in the code, with the tests that hold it. What is *not*
here is not built — and the second table says which of those are deliberately
deferred, with the reason, rather than simply absent.

The rule this page follows: **a row appears only when something would fail if the
capability were removed.** A feature with no test that can falsify it is not a
feature, it is an intention — the mechanisms that make that checkable are in
[operations](@/docs/operations.md).

## ✅ Built

| | |
|---|---|
| ✅ | **Tenant-keyed storage** — the tenant is a **key component** of every row on both backends, never a filter: a query that forgets it returns nothing rather than another tenant's rows. redb keys the journal, seal log, cases, events, timers, tasks and batches; `PostgreSQL` leads every primary key, unique index and foreign key with it. The tenant leads every time-ordered index, so a sweep or a worklist *ranges over* its own rather than filtering another's out, and counts are ranged rather than taken from the table. Two correlation paths matter most, both reachable because business keys are not globally unique: the case correlation index (a run joining another tenant's case would share its history, deadlines and erasure unit) and the subscription match index (one tenant's message resuming another's waiting run). Checked against a real Postgres with a *valid* identifier from the other tenant, which is the realistic leak → [erasure and keys](@/docs/erasure.md) |
| ✅ | **Tenant-aware serving** — one process serves many tenants: `Planes` maps an authenticated caller's tenant to that tenant's plane, and the gate hands the route the plane *with* the caller, so a handler cannot reach a store it did not resolve — the cross-tenant read is unspellable rather than guarded against. A caller whose tenant has no plane is **refused, never defaulted**, since a fallback turns an unregistered tenant into somebody else's data. Each plane answers under its **own** policy engine, so the laxest tenant's rules cannot set everybody's. The tenant comes from the credential like `actor` and `roles`, and on A2A it is checked twice — against the card *and* against the credential, because those can disagree and the disagreement is the attack. **Blob paths lead with the tenant**: content addressing otherwise puts two tenants' identical bytes in one object, and erasing it for one destroys the other's data while reporting both requests discharged → [erasure and keys](@/docs/erasure.md) |
| ✅ | **Per-tenant quotas** — ceilings on runs executing at once and on spend per billing period, accounted **in the store**, so they survive a second instance rather than doubling the moment somebody scales out. The reservation is one transaction that counts *and* inserts: a read-then-write leaves a window two instances admit through, and it widens under exactly the load the ceiling exists for. A refusal is its own error, not a policy denial — one says *you may not*, the other *not right now*, and collapsing them teaches callers to retry denials or abandon work that would succeed in a second. Checked at admission, so a refused run writes nothing; **never** on replay, or a ceiling crossed since would rewrite history into a refusal. Concurrency is a *set* of runs, not a counter: a crashed process strands a slot an operator can name rather than a number that has silently drifted. One battery holds both backends to it → [operations](@/docs/operations.md) |
| ✅ | **Per-tenant metric labels** — opt-in and **off by default**, because a tenant name is often a customer name and a metrics backend is usually the least protected system in a deployment. Cardinality is bounded by *configuration*: the label is this plane's own tenant, so the number of streams is the number of planes an operator wired and no request can grow it. There is deliberately no pseudonymous option: the tenant already appears in store keys, blob paths, the checkpoint origin and a publicly served Agent Card, so hashing it here would cover one exit of ten and invite the belief that it is contained — an id that is opaque to begin with covers all of them → [operations](@/docs/operations.md) |
| ✅ | Append-only, hash-chained journal — no record can be edited, reordered, or removed *within* a run |
| ✅ | **Record attestation** — every record optionally signed under a named identity, so the journal says *who wrote it*, not only what it says |
| ✅ | **Cross-run binding** — sealed runs enter a per-plane Merkle log with inclusion *and* consistency proofs, so an auditor can tell ordinary growth from a deletion; the per-run chain structurally cannot see either |
| ✅ | **Offline audit** — `audit::audit` runs against a store it did not write, and reports what it *could not* check as loudly as what failed |
| ✅ | Effect protocol — announce durably, act, record; at most once per run |
| ✅ | Replay (`Strict` verification) and resume (`Resume` crash recovery) |
| ✅ | Divergence detection — a changed build is quarantined, never allowed to silently rewrite history |
| ✅ | Exactly-once as a *database constraint*, not a code path |
| ✅ | **Run-ownership leases with epoch fencing** (split-brain safety), **renewed while a run executes** — the TTL bounds how long a *crashed* owner strands its runs, not how long a run may take. Without renewal a healthy run outliving its TTL is indistinguishable from a dead one, and is taken over and fenced mid-flight. A TTL under two seconds is refused at build: the stores keep expiry in whole seconds, so a shorter lease lapses between renewals however often they run |
| ✅ | Information-flow labels — trust/sensitivity lattice, egress ceilings, taint gates; **effect output is labelled at the source, untrusted by default** |
| ✅ | **Hierarchical argument provenance** — structured JSON retains labels per RFC 6901 path through plan field projection and object/array assembly. Outbound effects must use `cx.sink`, which canonically binds the exact dispatched arguments to the labels checked; generic `cx.effect` refuses them |
| ✅ | **Protected sink fields** — mutating tools can require trusted data, named provenance sources, and field-specific sensitivity ceilings for authority-bearing selectors while allowing ordinary untrusted content beside them. Manifest declarations are digest-covered and must exactly match the live catalogue |
| ✅ | **Typed, policy-authorized release** — trust and/or sensitivity can improve for the whole value or exact tracked fields only; every decision names its destination, basis and evidence, is authorized under `data:release`, retains provenance, and is journaled with the value digest plus prior/result labels. Release decisions occupy ordered effect keys, so changed evidence or semantics is replay divergence and strict replay never re-opens policy |
| ✅ | Journaled clock; reproducible per-step RNG |
| ✅ | Record schema versioning with pure upcasters |
| ✅ | **Cases** — correlation by business key, state across runs, closure rules |
| ✅ | **The instruction slot is authority-bearing** — `/system` is a protected field on a model call, so an instruction must be *trusted*. A model reads its order and its data as the same undifferentiated text, so a retrieved document saying *ignore previous instructions* is obeyed like one; every other control here bounds what the model may then **do**, and none of them answers who was allowed to give the order. Untrusted material belongs in `messages`, which forces the prompt to be built with `Tainted::object` — `map` cannot prove how a closure reshaped a value and taints the instruction with it → [security](@/docs/security.md) |
| ✅ | **Governed memory** — versioned items an agent keeps between runs, behind `RuntimeBuilder::memory`. Writable memory is **delayed code**: what is written today is read into a context window tomorrow, where a model treats it as established fact, so one poisoned write becomes a standing instruction. Two things answer that. A recalled item is labelled from **where it came from, never from what it says** — content-inferred trust is gameable, since text asserting its own reliability is the cheapest thing an attacker can write. And **retrieval is an effect**: the selection is journaled as ids, versions and content digests, so a replayed run re-materialises exactly what it read rather than re-running a search over a corpus that has moved. Writes append a version and supersede rather than edit, so forgetting is selective and reaches every version — an erasure that left history behind would be reported discharged while the data was still readable → [security](@/docs/security.md) |
| ✅ | **Compaction** — `cx.compact` summarises memories into a *derived memory*, and every hazard in that sentence is answered by the effect's shape. Its label is the **join of its inputs** and never declared by the caller, so summarising cannot launder untrusted memories into trusted ones. It carries a `max_sensitivity` ceiling on what the summarising model may be shown, defaulting to `Public`, because compaction is an *egress* and without a bound it would be the way to move confidential content past a limit that stops every other path — while looking like housekeeping. And it records the exact versions it absorbed, so forgetting a poisoned memory reaches what was derived from it: `forget` for a correction, which leaves legitimate summaries standing, `forget_cascading` for an erasure, which does not → [security](@/docs/security.md) |
| ✅ | **Deadlines** — pluggable `Calendar`, journaled instants, due sweep |
| ✅ | **Durable waits** — suspend on a correlated event; a waiting run is a row, not a thread |
| ✅ | **Durable timers** — `cx.sleep()` suspends the run; a sweep wakes it, and the instant is journaled |
| ✅ | **Event delivery** — arrival-order-independent, dead-lettered by sweep, deduplicated on **`(source, id)`** as CloudEvents defines uniqueness. Over HTTP the source is the authenticated caller, never a body field. The sender is journaled with the await and appears in provenance as `sender:…`, so a protected field can name one counterparty → [security](@/docs/security.md) |
| ✅ | **Human tasks** — worklist, four-eyes enforcement, declared expiry policy |
| ✅ | **Sweeper** — deadline warnings, breach escalation, task expiry, dead letters |
| ✅ | **Plan DAG** — contract validation, **concurrent** ready-set scheduling, provenance binding |
| ✅ | **Topology** — collaboration must justify itself; false parallelism is rejected |
| ✅ | **Replanning** — versioned successors with lineage; refused once untrusted data is in play |
| ✅ | **Budgets** — step/effect/token/cost/wall-clock limits, enforced deterministically |
| ✅ | **Retries** — gated on whether the call reached the peer, not on how the error looked |
| ✅ | **Reconciliation** — resolve an unknown outcome by asking the provider, not by assuming |
| ✅ | **Sagas** — reverse-order compensation, pivots, suspendable unwinds, and a refusal to unwind around doubt |
| ✅ | **Every case mutation is an effect** — a case's status and its obligations are shared mutable state that outlives the run, so both changes are journaled and neither is performed again on replay. A write outside the journal has two holes and the second is worse: replaying last quarter's history to answer a question would close a case that has since been reopened, and *who closed this and when* would have no record at all |
| ✅ | **Every feature builds alone** — `--all-features` cannot catch a feature that uses a module it never declared, and neither can a curated combination: it compiles whenever something else in the set happens to enable that module. `a2a-server` did exactly that with `push` and had never once been compiled by itself. `just features` now builds each optional feature on its own |
| ✅ | **The authorization decision can be re-derived** — policy is total and side-effect free so a third party can reach the same verdict offline, which only works if every input it consulted is on the record. The outbound value's **label** reached the policy request one revision before it reached the journal, so for that revision an auditor had to take the runtime's word that the right label was presented. `EffectStarted` now carries it, absent when an effect binds no value → [security](@/docs/security.md) |
| ✅ | **A specialist cannot hand off, in-plane either** — the role forbids delegation and the manifest refuses a specialist declaring a depth above zero. That was the *declaration* half, and for a while it was the only half: the ceiling was checked at delegating **sinks**, so it governed the A2A peer call and not `cx.commission` — the rule held across a network boundary and not across a function call. The loop the role exists to prevent, A→B→C→A, is the in-plane one: one process, no peer boundary to cross, no allowlist to notice. The check now sits on the path both take |
| ✅ | **A quarantine you can find** — a quarantine is the most serious conclusion this runtime reaches, and it used to produce a run status, an `error!` event and a counter: nothing an operator could ask for, and a run started with `spawn` returns before the status exists. Sealed runs are now indexed by how they ended, `GET /runs?outcome=quarantined` lists them, and the index is **derived** — the outcome's home is the chain, so it can be rebuilt and is never an authority. Longitudinal studies of production agent runtimes name this shape as the dominant failure: not an undetected fault, but a detected one whose signal never reached a human → [operations](@/docs/operations.md) |
| ✅ | **One matter, one scan** — the journal carries a record's case and indexes it, so *show me everything about this matter* is a range scan rather than a join over the case's runs. The difference is not only cost: a per-run walk **misses** every record written by a run the case does not own, which is exactly what a sweep is — so the record saying why a case was escalated would be unreachable from that case. Tenant-first, held to one conformance battery across both backends, and the battery checks that the scan finds this matter *and* returns no other |
| ✅ | **The sweep writes its own history** — breaching an obligation and escalating a case are the most consequential things the plane does *without being asked*, and nothing else records them. A tick that decides anything writes `Swept { subject, action, detail }` into a **sealed run of its own**, so it inherits the chain, the signature and the Merkle inclusion, and the external audit tool checks it without being taught what a sweep is. State alone cannot tell *the sweep breached this at 02:00* from *somebody set it*. A quiet tick writes nothing → [operations](@/docs/operations.md) |
| ✅ | **A capped sweep says it was capped** — each tick takes a bounded batch, because a sweeper still draining a backlog is one not noticing the next obligation. A bounded query returns a list shaped exactly like a complete one, so `SweepReport::saturated` names which sweeps came back full and `needs_attention()` is true when any did — otherwise a growing backlog and a quiet plane produce identical numbers → [operations](@/docs/operations.md) |
| ✅ | **Transactional effect groups** — the unit between an effect and a step, because a per-step saga leaves a gap: `Skill::compensate` receives the step's *output*, and a step that failed has none, so it is handed the absence of one and asked to guess. A group declares the **resources it touches** and refuses any member outside them; each reversible member records the concrete call that undoes it, built from that member's **actual output at the moment it landed** rather than reconstructed later from state that has moved. `commit` is the **frontier** — invariants are checked there because it is the last instant at which failing them is free — and only then are **deferred** members released. Deferral is what makes an irreversible send safe: an aborted group never sends it, which is a stronger statement than sending and apologising. Reversals dispatch through the ordinary effect path, so an undo is journaled, keyed, retried and metered like any other call, and never runs twice. Doubt reverses nothing → [architecture](@/docs/architecture.md) |
| ✅ | **Tracing** — run/step/effect spans, a dedicated event per loud failure, replay marked distinctly |
| ✅ | **Batches** — one frozen plan over N items, per-item journals, item-granular resume, partial failure as a terminal state |
| ✅ | **Delegation** — attenuating chains from a human owner down to the acting workload; widening is unrepresentable |
| ✅ | **Tool calls** — an operator-declared catalogue; a server's `readOnlyHint` can never make its own tool safe to repeat |
| ✅ | **Model calls** — usage journaled, and a completion that dies partway is billed for what it generated |
| ✅ | **Peer calls** — audience-bound credentials obtained by token exchange, refreshed before expiry, and never written to the journal |
| ✅ | **MCP** — real round trips over `rmcp`, behind the `mcp` feature; every transport failure states whether the call reached the server |
| ✅ | **Cedar** — the policy seam's first adapter, behind the `cedar` feature; strict startup validation, schema-aware request context, static entities, and policy evaluation failures reported as broken rather than ordinary refusals |
| ✅ | **Authorization** — a total, fail-closed policy seam; denials journaled, complete immutable policy-bundle identity recorded, open-run resume refused on drift, and strict replay never re-opens the gate |
| ✅ | **OpenTelemetry GenAI conventions** — the run span carries `gen_ai.operation.name = invoke_agent`; tool calls carry `execute_tool` and model calls `chat`, declared by the effect itself rather than sniffed from its name. Effects that are *not* GenAI operations carry no such attribute, which is what keeps it meaningful. The conventions are pre-1.0, so the version targeted is pinned rather than tracked |
| ✅ | **Metrics** — a declared catalogue of counters and observed gauges, guarded against declared-but-unemitted |
| ✅ | **redb** — the default embedded backend: pure Rust, two crates deep, ACID transactions across tables, stable on-disk format |
| ✅ | **PostgreSQL** — journal *and* case layer, for the shared-store topology |
| ✅ | **Store conformance batteries** — one contract per store, run against every backend, including a racing check no sequential test can replace |
| ✅ | **HTTP surface** — worklist, claim/release, decisions, run status, event delivery, behind the `http` feature; the wire types cannot express who is acting |
| ✅ | **Cancellation** — an operator stops a run; it unwinds what it did, refuses to unwind around an unknown outcome, and the record names who asked |
| ✅ | **A2A 1.0 `SendMessage` client** — the JSON-RPC method, ProtoJSON enums/parts, version and extension headers, response oneof, and conservative failure mapping are enforced behind the `a2a` feature; `-32006` and malformed post-dispatch responses are *in doubt*, while a failed/canceled/rejected task has *landed* |
| ✅ | **Witness cosigning** — the `Witness` seam and the decision that matters: a checkpoint is cosigned only if it *provably extends* the last one seen. A log that shrank is refused, and so is a second history of the same size — the split view. `MemoryWitness` implements it in-process |
| ✅ | **Envelope encryption and cryptographic erasure** — destroying a data key erases every copy at once, including backups taken before the request. `VaultTransit` puts the wrapping key in Vault. → [erasure and keys](@/docs/erasure.md) |
| ✅ | **Case-scoped erasure** — `erase_case` expires every blob a case produced, and nothing else. Bytes are linked to their case at write time through `cx.store_blob`, because a digest cannot be reversed later to find the matter it belonged to |
| ✅ | **Erasure with a tombstone** — a blob's bytes can be dropped while the chain still proves what happened, because the chain only ever committed to a digest. A reader afterwards gets `Expired` naming the date and reason, never `NotFound` — retention doing its job and data nobody can account for are different answers, and only one is an incident |
| ✅ | **Content-addressed blobs** — the claim check, with the reference being the digest, so the chain commits to bytes it does not hold; a blob altered on disk is refused, not served. In memory, or on anything OpenDAL reaches behind the `opendal` feature |
| ✅ | **A journal record size ceiling** — 1 MiB, refused rather than truncated, checked at the one point every backend seals through |
| ✅ | **System instructions** — written once as `system` on the prompt, spelled the way each API wants it: a top-level `system` on Anthropic, `instructions` on OpenAI Responses. In the effect key like the rest of the prompt, so editing the instruction shows up on replay as divergence |
| ✅ | **Governed multimodal ingestion** — provider-native remote URL forms remain refused before dispatch. The `media` feature adds exact HTTPS host/port grants, all-answer public-IP classification, DNS pinning, manual per-hop redirects, no ambient credentials/proxy/referrer/cookies/decompression, total/connect/read and header/body limits, MIME signature checks, versioned content validators, digest-only journaling, untrusted provenance, and case-linked or explicitly external retention. Digest markers materialize from verified blob storage only inside live model dispatch, so strict replay performs no DNS, HTTP, or blob read |
| ✅ | **Model drivers** — Anthropic Messages and OpenAI Responses behind the `providers` feature; reasoning tokens are billed, a cut-off answer says so, and a completion that generated and then declined is billed for what it generated |
| ✅ | **Structured output** — a JSON Schema enforced by the provider *during* generation and carried in the effect key; with forced-tool emulation for the many models that have no native support, and a refusal that names the rule when a schema is one strict mode cannot take |
| ✅ | **Quorum on high-risk nodes** — several judgements from *distinct declared lenses*, because identical judges share their blind spots; a split panel has no `majority()` to fall back on, so disagreement escalates rather than resolving itself |
| ✅ | **Network egress allowlists** — a model driver or peer client refuses a host nobody granted, before the request is built; no wildcards, and the allowlist never parses a URL itself so it cannot disagree with the client about what the host is |
| ✅ | **Attested provenance** — a tool call carries which run, case, effect and agent, signed by the plane's workload identity and **bound to the call itself**, so a callee can check the claim rather than believe whatever the last hop wrote; a signature over the identifiers alone would verify on any other request |
| ✅ | **Case state is a journaled effect** — mutable storage shared across runs is as non-deterministic as a clock, so a replay reads back what the live run saw instead of whatever the case holds now, and does not write on the way through |
| ✅ | **Case state cannot launder taint** — a read comes back *untrusted*, because case state is shared across runs and the engine never interprets it, so a read is only as trustworthy as the least trustworthy thing ever written. Returning it trusted was an exit from the lattice that bypassed `cx.release` entirely |
| ✅ | **Concurrent case writers** — a state write names the version it read and the store refuses it if the case moved, because the window between reading and writing contains a model call and two runs on one case overlap as a matter of course |
| ✅ | **Refusals do not teach** — a model is told one uniform sentence whatever the policy actually objected to, while the journal keeps the full reason for an auditor; a denial ceiling bounds the one bit uniformity cannot remove. Enforced at the one path where a refusal reaches a model — the tool-calling loop's failed-call result — and tested by reading what the *next turn was told*, not by calling `for_model` and asserting it is uniform. The second proves the function; only the first proves the runtime uses it |
| ✅ | **Streaming** — on by default for both drivers, because a severed call can then report *what it burned* rather than being billed as zero and retried for free; the SSE parser is hand-rolled precisely so it never reconnects, since a silently resumed stream is a second bill for one journaled effect |
| ✅ | **The provider asymmetry, named rather than smoothed over** — Anthropic reports usage incrementally so a cut stream bills real tokens; OpenAI reports it only at the end, so a cut stream knows it generated and not what it cost, and says exactly that |
| ✅ | **Cached-token accounting** — normalised across providers that report cache hits *inside* the input count and providers that report them *beside* it |
| ✅ | **Zeroized secrets** — API keys and bearer tokens are wiped when they drop and compared in constant time, not held in a `String` |
| ✅ | **An agent that is only a file** — `spec.execution.kind: completion` makes the runtime supply the behaviour, and the `agentplane` binary (`cli`) runs it: no `main`, no skill, no Rust. The digest therefore covers the agent *in its entirety* rather than only its boundary, and there is no accompanying program that could diverge from it |
| ✅ | **Oversight declared without a predicate** — `oversight.approval: required` makes a declarative agent open a task carrying its answer and return only on approval. Declaring it beside a *coded* agent is refused, because nothing there would apply it; `on_expiry: proceed` needs explicit consent; an unstated expiry denies |
| ✅ | **The manifest binds** — undeclared models/tools are refused and journaled; budgets bind; every sink uses the stricter of its own and `max_sensitivity_egress`; configured identities and handoffs are checked against `max_delegation_depth`. The unenforceable `security.pattern` label was removed rather than left as review-only intent |
| ✅ | **A lease can be handed back** — `release_lease` frees a run on orderly shutdown so a restart resumes at once, which is what lets the owner stay unique per process; a fenced caller's release is a no-op, so it cannot free the lease of whoever replaced it |
| ✅ | **A manifest is a reviewable file, not a builder call** — an agent's prompt, grants and ceilings are declared in YAML that a reviewer sees as a diff, and an unknown field is *refused* rather than ignored, because `max_tokns: 100` in a permissive parser silently means no token ceiling at all |
| ✅ | **A prompt with a version** — the system prompt lives inside the digested manifest, so rewording it is a version bump rather than a deploy nothing records; a prompt composed in the embedder's code has no version at all |
| ✅ | **A runtime runs agents; it is not one** — a plane owns the journal, stores and drivers; an agent owns a manifest and its skills. `StepCtx::commission` hands work to a peer agent as a journaled effect, so it replays and its spend is billed to whoever ordered it → [architecture](@/docs/architecture.md) |
| ✅ | **The multi-agent arrangement is declared, not emergent** — `topology.mode` (`single`/`routed`/`collaborative`) and `topology.role` (`specialist`/`orchestrator`/`router`) are in the manifest, and three incoherent combinations are refused: a specialist that may delegate, a lone agent with a coordinating role, and collaboration with no declared justification |
| ✅ | **A model swap is a version bump** — provider and model id live in the digested manifest, so changing either changes the declaration consumers pin; privileged, quarantined, and fallback roles form the reviewed model allowlist |
| ✅ | **A result contract with a version** — `spec.output.schema` is digest-covered, and handed to `ModelCall::expecting` it enters the effect key, so editing it makes a replay report divergence rather than reinterpreting a stored answer. `schema: {}` is refused: it permits anything while looking answered |
| ✅ | **A manifest can be signed, and the signature says *what for*** — `publish_signed` / `resolve_verified` answer "who published this", which no digest can. Signed over a domain-separated hash, so a manifest signature cannot be presented as a record attestation and vice versa. Unsigned and badly-signed are reported distinctly: one is an operational fact, the other an incident |
| ✅ | **Checkpoints in the envelope a witness accepts** — C2SP `signed-note`, the encoding Go's checksum database, Sigstore and Sigsum use, so a checkpoint from here is cosignable by witnesses nobody here operates. The em dash, the separating blank line and the `key_id ‖ signature` payload are each pinned by a test, because each is a way to produce a note that serialises fine and verifies nowhere |
| ✅ | **Checkpoint signing may live in a KMS** — `CheckpointSigner` is async and fallible, unlike the per-record `Signer`, which stays I/O-free because it runs on every append. The witness key is the trust anchor, and an anchor whose key sits beside the history it vouches for is one a single compromise removes |
| ✅ | **A registry that refuses to rewrite history or authorship** — a published version is immutable, so "we reviewed 2.0.0" describes an artifact rather than a Tuesday. Identical unsigned content may adopt its first publisher attestation, but an existing publisher cannot be silently reassigned; and a resolve can be pinned to a digest, which is the check that still holds when the registry itself is the compromised party. The shipped registry is in-process only; a durable or remote implementation is not built |
| ✅ | **A fake provider** — `testkit::FakeProvider`, so tests and examples can exercise the model path with no key and no network; deterministic by construction, never reports a call as free, and refuses to answer as a real provider so a fake-produced journal cannot read as a genuine one |

## 🚧 Designed, not built

These are designed and unimplemented. Each row says what is missing and why it
is still open, so an evaluator can tell "deliberately deferred" from "never
thought about" — the distinction a status page exists to make.

| | |
|---|---|
| ✅ | **A tool is one type** — its arguments are its fields, its schema comes from those fields and its description from the doc comment, so a model is shown exactly what the body will receive. `call` takes `self`: by the time it runs the model's JSON *is* the type or the call was refused, so there is no `Value` to index and no field to misspell — the old shape read `arguments["id"].as_str().unwrap_or(…)` and turned a renamed field into a plausible wrong answer. Dispatch by name happens once inside the crate rather than in an `if` at the top of every `ToolClient`. And `RuntimeBuilder::toolbox` makes that one call: it derives the catalogue from each agent's own declaration and **refuses to build** where the code and the reviewed manifest have drifted **either way** — a tool implemented but never granted, or granted with nothing behind it, or a manifest relaxing a tool's own claim that it mutates. The check runs at `build` rather than when the box is wired, so it cannot be lost by reordering the builder, and every agent on the plane is checked rather than the first |
| ✅ | **A catalogue may be stricter than a grant, never laxer** — the two places a tool's safety can be written are the reviewed manifest and the operator's catalogue, and only one of them is what the *effect* reads. A catalogue calling a reviewed-mutating tool read-only therefore drops the whole-value taint gate and makes a timed-out money-moving call retryable, which is the one direction nobody can be right about. Refused at build; and the taint gate takes the stricter of the two regardless, because the authorization gate had ORed the manifest's `mutates` in since it existed and the sink gate beside it had not. Two agents on one plane granting one tool **differently** is refused for the same reason: a plane has one catalogue, so merging by last-writer resolves a reviewed disagreement by registration order and refuses the losing agent every call to that tool, in production |
| ✅ | **A tool is declared once** — `ToolCatalog::from_manifest` derives the operator's catalogue from the agent's declaration. A manifest and a catalogue are two parties speaking, which is real when they are two people and pure tax when they are one: stating `mutates`, the ceiling and the protected fields twice is one decision written twice and a chance to disagree about it. An operator who genuinely differs still calls `.allow(...)`, and the manifest's grant is re-checked at dispatch either way — deriving can only narrow, never widen |
| ✅ | **A failed tool call says only what the model may act on** — the far side's own answer reaches it, because a tool that was unreachable or ran and declined is what the model needs in order to try something else, and it is text the far side already controls. A refusal produced *here* is one uniform sentence. And an outcome that is **unknown** is not a failed call at all: it leaves the loop so the executor quarantines, because a timed-out payment may well have been taken and reporting it as a failure lets the model apologise, continue, and end the run `Succeeded` over a mutation nobody can account for → [security](@/docs/security.md) |
| ✅ | **Tool calling, declared and governed** — `execution.kind: tool-calling` runs the loop from a file. The model is offered exactly the manifest's grants, with their declared descriptions and argument schemas; the name it picks is matched **byte for byte**, and one matching nothing returns as a failed call so it can correct itself. Arguments stay untrusted, so grants and the egress ceiling apply. `max_turns` bounds it, and an agent still asking when it runs out fails rather than passing off half-formed reasoning. Every turn is a journaled effect → [security](@/docs/security.md) |
| ✅ | **Transactional group members** — where the resource lives in the **same database as the journal**, `g.atomic(...)` commits the member's write and the record that it happened in one transaction. Strictly stronger than the saga form and for a reason worth stating: nothing is externalised and later reversed, so no reversal can fail; there is no in-doubt state, because a transaction either committed or did not; and an abort is a `ROLLBACK`, which cannot itself fail halfway. Compensation that never has to run beats compensation that runs correctly. The seam is SQL because the premise is that the table is *already there* — a store that cannot lend its transaction answers `None`, and the member is refused at **registration**, the only time refusing is free → [architecture](@/docs/architecture.md) |
| ⬜ | **A Bedrock driver** — the enterprise default for exactly this project's audience, and writable **today with no crate changes**: `ModelProvider` hands a driver a `Request` of `{model, prompt, schema, tools, exchanges}` and carries no provider bias, which was verified rather than assumed. It is not shipped because the valuable half is not the transport but the **failure mapping** — `ThrottlingException`, `ModelTimeoutException` and `ModelErrorException` mean different things about whether the call landed, and a driver that guessed would put `InDoubt` where `DidNotHappen` belongs. Converse also unifies several model families behind one wire format, so one driver is worth doing properly rather than quickly |
| ⬜ | **Wasm skill tier** — the capability-absence sandbox where determinism is enforced rather than requested. The native tier is trusted by definition, which is recorded as a residual risk rather than a control |
| ⬜ | **Symbolic policy analysis** — Cedar's `symcc` can *prove* properties of a policy set rather than test them; nothing invokes it yet. It needs an external **cvc5** solver binary, so when it lands it will be a development-time check you run when policy changes — never a runtime dependency, and never in the shipped binary |
| ✅ | **A remote witness** — `HttpWitness` speaks C2SP `tlog-witness`, so checkpoints can be cosigned by the existing public network (`transparency-dev`'s omniwitness and `ArmoredWitness`, already cosigning for Go's sum database, Sigstore, Sigsum and LVFS). A **409 is reported as a stale cursor, never as a fork** — the first is a routine retry, the second an integrity incident, and conflating them is how the alert that matters stops being believed. What remains is a witness *policy*: how many cosignatures suffice, and what a run does when witnesses are unreachable |
| ✅ | **A2A server** — this plane, callable by other agents, behind `a2a-server`. The public card is served at `/.well-known/agent-card.json` and every JSON-RPC method authenticates and authorizes; it is a **separate router** because a surface whose invariant is "every route authenticates" must not grow one exception. `SendMessage` (blocking by default, `returnImmediately` supported), `GetTask`, `CancelTask` and `GetExtendedAgentCard` are implemented under the 1.0 names — the 0.3 spellings are refused, since a server answering both accepts clients that have silently lost half the protocol. A peer's message is admitted **untrusted**, provenanced `peer:<caller>`. The capability is **named, never inferred**: with several skills advertised and none named the call is refused, because guessing would let the sender pick what runs by writing text. Unimplemented operations return the spec's own codes so a caller can tell *cannot* from *misspelled*, and a policy denial is a `Message` decline rather than an internal error → [security](@/docs/security.md) |
| ✅ | **A2A streaming** — `SendStreamingMessage` and `SubscribeToTask` over SSE, read from the **journal** rather than an in-process channel. That is what makes the stream as durable as the run: a client that drops and re-subscribes is told the current state and continues, any instance can serve it, and the events cannot disagree with history because they *are* history. A channel would lose all three. The cost is a poll per subscriber, stated rather than hidden. Streams close on a terminal state **and** on suspension — a run waiting a week on a human is not a stream, and reconnecting costs nothing when the stream is rebuilt from history → [architecture](@/docs/architecture.md) |
| ✅ | **A2A push notifications** — durable webhook registrations plus SSRF-guarded delivery, behind `push`. This is the one place an **untrusted party names an address this plane connects to**, so three controls stack: an operator **host grant**, **HTTPS only**, and **every resolved address checked** with the connection pinned to them — a name answering with one public and one private address reaches nothing. The grant is re-checked at delivery, not only at registration, so revoking a host stops notifications for tasks registered while it was granted. The payload carries the task's **state, not its output**: a webhook is an endpoint we were merely told about, and an allowlist plus a body is an exfiltration channel. Tokens are stored as secrets, never echoed back, and never printable. Registrations are tenant-keyed — a task id is not a capability → [security](@/docs/security.md) |
| ✅ | **Agent Cards derived, not written** — an A2A v1.0 card built from the manifest, so what an agent advertises and what it is permitted cannot drift. Unimplemented transports are advertised as **absent**. `ExtendedAgentCard` is the authenticated variant and a **separate type**, so serving it publicly is a compile error; it withholds the model and the protected-field rules |
| ✅ | **Signed Agent Cards** — a detached JWS (RFC 7515) over the card canonicalized per RFC 8785, so a peer can check *who published it* rather than only which host served it — and it keeps checking after the card is copied into a registry or a cache. A real JWS, signed over the standard signing input rather than its hash: signing `H(m)` verifies against our own code and nothing else. The algorithm is read from a **constant**, never from the card being checked, which is the `alg: none` attack on the one document an attacker fully controls. Signed at publish so the signature covers the interface URL and tenant as served. Several signatures coexist, so key rotation has no window. Canonicalization is UTF-16-ordered per the RFC, and a guard asserts the card carries no numbers — the one JCS rule this crate does not implement |
| ✅ | **Client-side card discovery, verification and interface selection** — `CardClient` fetches an agent's card from the well-known path under an **egress allowlist**, because dereferencing a URL from a config or a registry entry is how a plane is made to probe its own network. Verification is opt-in and, once on, **mandatory**: an unsigned card is refused, since the downgrade is removing the signature rather than forging one. Interface selection matches binding *and* `Major.Minor` version in card order, and carries the interface's `tenant` into the endpoint — without it a client can only ever reach an agent serving the default tenant. A card still grants **nothing**: peer authority comes from the operator registry, so a forged card can waste a request and cannot widen one |

## 🔍 How to check this page is honest

```sh
just anchors    # every mutation still anchors in the code it names
just features   # every optional feature compiles on its own
just ci         # lint, feature configurations, examples, docs, packaging
just ci-full    # the above, plus TLA+ specs and the full mutation sweep

python3 tools/mutants.py <name> --verify   # one guarantee, end to end
```

The mutation sweep is the one that matters for this page: it breaks each
guarantee on purpose and requires the test *written for it* to fail. A row here
whose guarantee could be deleted without a test noticing would be caught by that
sweep, not by review.

`--verify` is the same check for a single row, and it exists because the cheap
one is not enough. `just anchors` proves a mutation still *matches* the code;
only running it proves the mutation still *kills*. A test rewritten around a
mutation passes quietly, and a guarantee that stopped being checked looks
exactly like one that is. The feature set comes from the test's own `cfg` gates
rather than a second list, so there is nothing to keep in step — and the command
distinguishes **survived** from **never ran**, because a run that compiled
nothing reports zero failures and reads like success.
